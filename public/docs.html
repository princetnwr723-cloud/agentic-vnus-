Overview

Agentic Vnus

A self-improving AI agent that runs entirely on your PC — no cloud, no API keys on most plans, no data leaving your machine. It learns from your usage and gets better every day.

🔒 100% Local
All AI inference runs on your machine via Ollama. Your commands, files, and data never leave your PC.
🧠 Self-Improving
Agent learns your preferences, saves successful task patterns as skills, and gets faster at repeated work.
🌐 Browser Control
Full Playwright-powered browser automation — search, fill forms, extract data, navigate any website.
💻 GitHub Native
Read, write, commit, create PRs and issues — all via GitHub REST API, no git commands needed.

Quick Start

Getting Started

From download to your first command — takes about 10 minutes including model download.

  • 1
    Download the Agent
    Go to your dashboard → Set Up Agent → Download for your OS (Windows, Mac Intel, Mac Apple Silicon, or Linux).
  • 2
    Install & Launch
    Run the installer. On Windows, if asked "Vnus Agent cannot be closed" — the agent was already running. Click Retry. It auto-closes the old version and continues.
  • 3
    Copy Your 10-Character Code
    The splash screen shows your permanent connection code — same machine always gets the same code. Copy it.
  • 4
    Connect on Website
    Go to your dashboard → Add Workspace → paste the code → Connect. Your PC is now linked to your account.
  • 5
    Choose a Plan
    Pick Free, Starter, Pro, or higher. Free plan activates immediately. Paid plans go through Gumroad checkout — plan activates automatically after payment.
  • 6
    Select & Download Your Model
    The app detects your RAM and suggests the best model. Click Download — Ollama installs automatically if needed. Large models (6–19GB) take a few minutes on first download.
  • 7
    Start Giving Commands
    Workspace opens. Type a command like "Open Chrome and search for AI news" or "Create a Python file on Desktop". Agent executes it on your PC.
⚠️ First Download Takes Time

Ollama and the AI model download only once. After that, everything runs offline. A 6GB model on a 50 Mbps connection takes about 15 minutes.

Architecture

How It Works

Agentic Vnus runs as an Electron desktop app on your PC. It uses a local Ollama model to understand your commands and translate them into actions. Commands come from your browser via Firestore — the agent polls every 3 seconds.

Request Flow

You type a command
→
Firebase Firestore
→
Agent polls (3s)
→
Local Ollama LLM
→
JSON actions
→
Executed on PC
→
Result back to you

Core Components

ComponentFileWhat It Does
brain.jssrc/agent/Core intelligence — builds system prompt with memory, calls Ollama, parses JSON actions, executes them
memory.jssrc/agent/Persistent memory — saves user preferences, facts, corrections, session history to disk
skills.jssrc/agent/Self-improving skills — detects patterns in successful tasks and generates reusable skill files
listener.jssrc/agent/Firestore polling — checks for new commands every 3 seconds, marks them processing, sends results back
ollamaManager.jssrc/agent/Manages Ollama — installs if missing, checks version, downloads models with progress
browserAgent.jssrc/agent/Playwright browser — click, type, navigate, extract data from any website
githubAgent.jssrc/agent/GitHub API — read/write files, create repos, branches, PRs, issues
main.jssrc/Electron entry point — window management, IPC, startup, tray icon

The LLM never sees your actual files unless you explicitly ask it to read them. The agent only acts on your commands — it does not run autonomously in the background.

Critical Rule

The 50% RAM Rule

⚠️ This Rule Always Applies — No Exceptions

The AI model must use no more than 50% of your total RAM. This keeps your PC running smoothly while the agent works. You cannot override this limit.

If a model is larger than 50% of your total RAM, the agent will not offer it — even if you are on the Elite plan. Your plan determines which models are available to you, but your RAM determines which ones actually run.

Learning System

Memory System

The agent saves what it learns about you across sessions. Unlike cloud AI agents, this memory lives in ~/.vnus-agent/memory.json on your PC — completely private.

What Gets Remembered

User Preferences
Preferred browser, editor, default save location, working directory, language. Learned from your commands automatically.
Important Facts
Up to 50 facts about your setup — GitHub username, known file paths, app locations, project details.
Corrections
When you correct the agent, it remembers what went wrong and avoids repeating the same mistake in future sessions.
Session History
Last 100 sessions saved. Agent can search past sessions to recall what was done earlier ("what did I work on last week?").

Memory Location

~/.vnus-agent/
├── memory.json        # User profile + facts + preferences
├── skills/            # Auto-generated skill files
│   ├── open_chrome.json
│   ├── send_email.json
│   └── ...
└── sessions/          # Session history (last 100)
    ├── session_1.json
    └── ...

Memory is injected into the system prompt at the start of every command — the agent always has full context of who you are and what you prefer, without you repeating yourself.

Self-Improvement

Self-Improving Skills

Every time you successfully complete a task, the agent analyzes it. If it detects a repeatable pattern, it automatically generates a skill file. Next time you ask for the same type of task, the skill runs directly — no LLM call needed for the planning step, which makes it faster.

How Skills Work

  • 1
    You complete a task successfully
    Example: "Open Chrome and search for AI news" — agent opens Chrome, navigates to Google, types the query.
  • 2
    Pattern is detected
    Agent checks if this matches a known pattern (browser task, email, file creation, GitHub operation). After the first success, a skill candidate is tracked.
  • 3
    Skill file is generated
    A JSON skill file is saved in ~/.vnus-agent/skills/ with the action pattern, triggers, and success count.
  • 4
    Skill is available for future tasks
    Next time you ask something similar, the skill appears in the system prompt. The agent uses the proven pattern instead of figuring it out from scratch.

Skills improve over time. A skill used 10 times is more reliable than one used once. The agent tracks success counts and sorts by reliability.

Integration

GitHub Integration

GitHub operations use the REST API directly — no git commands, no local git installation needed. Your token is stored locally in ~/.vnus-agent/github-state.json.

Important

Warnings & Known Limitations

⚠️ Small Models Make Mistakes

On 8 GB RAM, the agent uses Qwen 3.5 4B or Phi-4 Mini. These models are capable but not perfect. They may misunderstand complex multi-step commands, generate incorrect file paths, or choose wrong CSS selectors for browser tasks. If a command fails, rephrase it more specifically and try again.

⚠️ No Undo for Destructive Actions

The agent can delete files, run terminal commands, and push to GitHub. There is no confirmation step before these actions. Always verify your command before sending. Dangerous commands like rm -rf / or format c: are blocked, but be careful with delete commands.

⚠️ Internet Required for Setup

Ollama and AI models download from the internet on first setup. After that, the agent works completely offline. If your internet is slow, model downloads may take a long time — a 19 GB model takes ~1 hour on 50 Mbps.

⚠️ PC Performance During Inference

When the AI model processes your command, it uses significant CPU/RAM. Your PC may feel slower for 5–30 seconds per command depending on model size. This is normal. The 50% RAM rule reduces this impact.

⚠️ Gmail & Email Limitations

Email sending works through browser automation — the agent opens Gmail or Outlook and fills in the compose window. This requires the browser to be logged in. Direct SMTP email API is not yet supported (coming in a future update).

⚠️ CAPTCHA Cannot Be Bypassed

Any website that shows CAPTCHA during automation will block the agent. This includes some bank websites, government portals, and heavily protected login pages.

⚠️ Ollama Version Requirement

The agent requires Ollama v0.1.40 or later. If an older version is installed, the agent will automatically update it. This requires an internet connection and takes a few minutes.

FAQ

Frequently Asked Questions

Does the agent work offline?

Yes — after the first setup (Ollama + model download), everything runs offline. Your commands never reach any external server. The only internet usage after setup is fetching commands from Firestore (a few hundred bytes per poll) and GitHub API calls if you use GitHub features.

Where does my data go?

Commands you type are stored in Firestore temporarily (to relay them to your PC). AI processing happens entirely on your machine. Files you create, GitHub tokens, and memory are stored locally in ~/.vnus-agent/ and your userData folder — never on our servers.

How do I reconnect after disconnect?

Open the agent app — it will show your code again. Go to Dashboard → Add Workspace → enter the code. Your permanent code never changes as long as you're on the same machine.

How do I delete a downloaded model?

ollama rm qwen3.5:4b

Run this in Terminal / Command Prompt. Then reopen the agent — the model picker will appear again so you can download a different model.

Can I use the agent on multiple PCs?

Yes — each PC gets its own unique 10-character code. Add as many workspaces as your plan allows. Each workspace runs independently with its own model and memory.

What happens if model download fails?

The agent shows an error screen with the specific reason and a Retry button. Your plan stays active — just retry the download. If it keeps failing, check your internet connection and disk space (you need at least 2 GB more than the model size).

Does the agent run in the background?

Yes — it minimizes to the system tray. As long as the tray icon is visible, the agent is running and listening for commands. Close it by right-clicking the tray icon → Quit.

Technical Reference

Architecture Deep Dive

For developers who want to understand exactly how the agent works internally.

brain.js — The Core

Every command goes through brain.js. It builds a system prompt that includes your memory context and available skills, sends it to Ollama, receives a JSON array of actions, and executes them one by one. If a browser action fails, execution continues with the next action rather than stopping.

Command → buildSystemPrompt() → Ollama API call
       → parseActions(text)   → executeActions(actions)
       → extractLearnings()   → shouldCreateSkill()
       → saveSession()

memory.js — Persistence Layer

Reads and writes ~/.vnus-agent/memory.json. The buildMemoryPrompt() function generates a formatted string that gets injected into every system prompt — so the AI always knows your name, preferences, corrections, and known paths without you repeating them.

skills.js — Pattern Recognition

After each successful task, shouldCreateSkill() checks if the command matches any of 5 built-in patterns (browser search, email, file creation, GitHub, app open). If a match is found after the minimum number of successful uses, generateSkill() creates a JSON file in ~/.vnus-agent/skills/. Skills include trigger phrases, action templates, and success counts.

ollamaManager.js — Model Lifecycle

Handles the complete Ollama lifecycle: version check → install/update if needed → start server → check if model exists → pull if missing. Uses streaming pull API so download progress is shown in real time. Falls back to reinstall if the version is below 0.1.40.

listener.js — Command Polling

Polls Firestore every 3 seconds using the REST API (no Firebase SDK in Electron — uses plain fetch). Uses a Set to track in-progress commands and avoid double-execution. Commands are executed asynchronously so the poll loop never blocks.

Action Execution Priority

1. Browser actions (browser_*) — most reliable for web tasks
2. PC control (open, click, type) — for native apps
3. File operations (write_file, read_file) — always works
4. GitHub API (github_*) — requires token
5. Shell commands (run_command) — most powerful, use carefully
⚠️ run_command Has No Sandbox

The run_command action runs any shell command with the permissions of the current user. Certain dangerous commands are blocklisted, but this action is powerful. Only use it when you trust the command being executed.
